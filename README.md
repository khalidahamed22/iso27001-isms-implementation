
# ISO/IEC 27001:2022 ISMS Implementation Portfolio

## Project Overview

This repository demonstrates a simulated end-to-end implementation of an Information Security Management System (ISMS) based on ISO/IEC 27001:2022.

The project covers organisational context, information security risk management, risk treatment, policies and procedures, control implementation planning, evidence management, internal audit, management review, corrective actions, and readiness assessment.

The objective is to demonstrate practical knowledge of how an organisation can establish, implement, maintain, and continually improve an ISMS.

## Organisation Profile

**Company:** CloudLedger Technologies (Pvt) Ltd  
**Industry:** SaaS / Financial Technology  
**Head Office:** Colombo, Sri Lanka  
**Employees:** 120  
**Business Customers:** 500  
**Cloud Platform:** Amazon Web Services (AWS)

CloudLedger Technologies is a fictional SaaS provider offering financial management services to business customers.

The organisation processes customer personal information, financial transaction records, employee information, application source code, and authentication information.

## Project Objectives

- Define the ISMS context, interested parties, and scope.
- Establish an information security risk assessment methodology.
- Identify and evaluate information security risks.
- Develop a risk treatment plan.
- Prepare a Statement of Applicability covering Annex A controls.
- Develop information security policies, procedures, and standards.
- Define control implementation activities.
- Prepare sample operational records and evidence registers.
- Establish internal audit and management review arrangements.
- Define corrective action and continual improvement processes.
- Prepare an ISO 27001 readiness assessment framework.

## Implementation Framework

The project follows the main ISO/IEC 27001:2022 ISMS structure:

| ISO 27001 Clause | Implementation Area |
|---|---|
| Clause 4 | Context of the Organisation |
| Clause 5 | Leadership |
| Clause 6 | Planning |
| Clause 7 | Support |
| Clause 8 | Operation |
| Clause 9 | Performance Evaluation |
| Clause 10 | Improvement |

Annex A controls are considered through risk assessment, risk treatment, applicable requirements, and the Statement of Applicability.

## Risk Management Approach

Information security risks are assessed using a simulated likelihood and impact methodology.

Risks are linked to organisational assets and evaluated based on their potential impact on:

- Confidentiality
- Integrity
- Availability

Risk treatment options include modifying, avoiding, sharing, or retaining risks, subject to organisational criteria and management approval.

The Statement of Applicability records control applicability, justification, and implementation status.

## Evidence and Documentation

The repository contains documentation and illustrative records designed to demonstrate how an ISMS can be managed.

Examples include:

- Asset inventory and classification registers.
- Access request and revocation records.
- Supplier security assessments.
- Vulnerability management records.
- Backup and restoration testing records.
- Security incident records.
- Change management records.
- Internal audit documentation.
- Management review records.
- Corrective action registers.

The presence of a document does not establish that a control has been implemented or is effective. Operational evidence and verification are necessary.
